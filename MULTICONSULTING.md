# MULTICONSULTING

Método exclusivo de este piloto MONTARA-BRAIN. Todos los agentes tienen acceso al conector GitHub cuando esté autorizado. Elegir conector remoto por destino, permisos, disponibilidad, cuota y concurrencia. Priorizar herramientas específicas cuando correspondan; agrupar inspecciones compatibles en scripts acotados si el proveedor lo permite. Nunca eludir autorizaciones, cuotas, políticas o límites. Separar cambios sensibles de inspección y validación. Usar rutas explícitas, tiempos máximos, resultados compactos y pruebas sintéticas. Ante escritura incierta, verificar antes de repetir. Para trabajos largos, usar mecanismos asíncronos nativos y recuperar resultados por identificador sin sondeo excesivo.

Preferencias: SentinelX para scripts y trabajos asíncronos; MCPENROUZ para terminal persistente; EXZA para archivos y operaciones rápidas durante sesión autorizada; Desktop Commander como respaldo y acceso avanzado a Projects. No asumir acceso al mismo servidor ni cuotas independientes. No replicar credenciales de GitHub CLI entre agentes sin autorización. No acceder a otros proyectos ni a credenciales privadas. Los detalles de infraestructura quedan fuera de este repositorio público.

FER decide asignaciones y cambios de permisos. Work/Codex auditan, no orquestan.
